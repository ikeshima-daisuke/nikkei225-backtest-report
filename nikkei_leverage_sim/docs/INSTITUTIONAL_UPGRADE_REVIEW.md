> **種別:** 方針レビュー（実装なし） / **日付:** 2026-06-05

> **対象:** `nikkei_leverage_sim` — 1570.T（日経レバ2倍ETF）信用ロング積立・損切り禁止・利確のみのバックテスター
> **目的:** 計算資源が潤沢である前提で、検証基盤を「機関投資家レベルの精度」に引き上げる際の優先順位付け

## 0. 総括（3分で読める版）

いま一番やるべきは「**儲けを増やす研究**」ではなく「**どこまで耐えられるかを正しく測る研究**」。

この戦略は「損切りせず、利が乗った時だけ売る」形のため、**普段はコツコツ勝てるが大暴落で一気に大損する**タイプ。平均点（シャープレシオ等）を磨いても、肝心の「最悪のとき何が起きるか」が見えていなければ意味がない——これが Codex と Claude の共通見解。

効果が高い順に：

1. **暴落シミュレーション** — 2008/2020 のような相場を再現し、最大含み損と資金が尽きる点を測る
2. **"最悪"を測る指標を主役に** — 平均ではなく「一番ひどい日の資産」「下落の深さ」を表のトップへ
3. **"まぐれ当たり"を見破る統計チェック** — 偶然うまくいったパラメータを選んでいないか検証
4. **「売りたい時に本当に売れるか」をリアルに** — 暴落時は板が薄く、思った値段で利確できない
5. **結果を監査できる形で残す** — CSV保存・乱数seed固定で誰でも再現可能に

> ⚠️ **最重要:** 信用取引では「損切り禁止」は実は不可能。証拠金維持率が一定ラインを割ると証券会社が**強制決済（追証）**する。これを無視したシミュレーションは現実より楽観的。→ **本件は Week 0.5 / PR #4 で着手済み**（forced liquidation + seed 記録）。本ロードマップはその続き（Week 1+）。

派手な最適化（探索強化）は最後でよい。土台が緩いまま最適化すると「精密に間違える」だけ。

## 2. Codex 推奨 上位5項目（ROI順）

| 順位 | 項目 | 一言で |
|---|---|---|
| 1 | **D1. ストレステスト充実** | 暴落時の破綻確率・追証耐性を直接測る。この戦略の本丸 |
| 2 | **C. 評価指標強化** | シャープでは危険が隠れる。CVaR/Ulcer/最悪日資産を主指標に |
| 3 | **A. 統計的検証強化** | WF＋random search は過剰最適化を起こす。purged CV で潰す |
| 4 | **D2. 約定モデル現実化** | レバETFの寄付は薄い。「売りたい時に売れない」を再現 |
| 5 | **F. レポート品質** | 再現性・監査可能性・ベンチ比較が"精度"そのもの |

### D1. ストレステスト充実 〔最優先〕
- **理由:** 「損切り禁止＋利確のみ」では平均成績より、暴落時の追証・資金拘束・回復不能リスクが支配的。最も直接的に破綻確率とテール耐性を測れる。
- **実装方針:** 2008/2011/2015/2020/2024 を個別レジームとして切り出し、資産推移・含み損ピーク・最低維持率・追証発生日を出力。`arch` ／自前 moving/block bootstrap で Monte Carlo 経路を生成し、スリッページ 2–20bps・信用金利 1.5–6.0%・ギャップダウンを感応度分析。
- **落とし穴:** 1570.T 上場前（2012以前）を単純接続すると ETF 固有の乖離・減価・制度変更を過小評価する。

### C. 評価指標強化
- **理由:** シャープや年率リターンはこの戦略の危険を隠す。CVaR・Ulcer Index・maxDD分布・最悪日資産・追証距離を主指標に。
- **実装方針:** Sortino / Calmar / Ulcer Index / VaR95 / CVaR95 / maxDD percentile / skew / kurtosis / 最低証拠金維持率を標準出力化。`empyrical` / `quantstats` / `scipy.stats` / `numpy` / `pandas` で十分。
- **落とし穴:** 日次リターン系列だけで評価すると信用建玉・含み損・税後CFの非線形性を落とす。必ず**ポジション・現金・評価損益ベース**で算出。

### A. 統計的検証強化
- **理由:** ウォークフォワード＋random search は多重検定・過剰最適化を起こす。利確条件だけを最適化する非対称戦略は、偶然うまく逃げたパラメータを選びやすい。
- **実装方針:** purged K-fold 時系列CV / embargo 付き train-val split / block bootstrap 信頼区間 / 置換検定 / Benjamini-Hochberg FDR補正。`mlfinlab` 系の考え方・`sklearn` 互換CV・自前 purging・`statsmodels`。
- **落とし穴:** 通常の K-fold やランダム分割は時系列リークになり、有意性を過大評価する。

### D2. 約定モデル現実化
- **理由:** 翌寄付 Open 約定は保守的に見える場合もあるが、レバETFの寄付はギャップ・流動性集中・板薄化の影響を受ける。追証近辺で「売りたい時に利確できない」が致命傷。
- **実装方針:** Open に加え VWAP / TWAP / 始値からの不利方向スリッページ / 出来高参加率 / 部分約定 / 約定遅延 をシナリオ化。`pandas_market_calendars`・分足・可能なら板/約定履歴。
- **落とし穴:** 1570.T は流動性が高いと market impact をゼロ扱いしがち。ストレス時の流動性低下は別パラメータに。

### F. レポート品質
- **理由:** 機関投資家レベルでは再現性・監査可能性・ベンチマーク比較が精度そのもの。単独戦略の成績だけではリスクを取る必然性を説明できない。
- **実装方針:** 取引・建玉・日次資産・税・金利・追証距離・パラメータ・**乱数seed** を CSV/parquet で構造化保存。B&H / RSI naive / MA cross naive / 現金比較を自動生成し README・PR本文へ主要リスク数値を埋め込む。
- **落とし穴:** 平均リターン中心のレポートに戻ること。主表は「最悪日資産・最大含み損・CVaR・追証発生率」に。

## 3. 除外候補

- **B. 最適化手法強化（Optuna TPE / Pareto / 試行1000+）:** 手法自体は有用だが、検証・ストレス・約定現実化の前に強化すると「過剰最適化を高精度に行うだけ」になりやすい。土台を固めた後に。
- **E. 指標・シグナル増強（マクロ / 出来高OI / センチメント）:** データスヌーピングの温床。まず既存戦略の破綻確率を正しく測る方が ROI が高い。

## 5. Claude の評価と追加視点

**大筋で同意。** 「D1・C を最優先、B を後回し」という順序は正しい。損切り禁止＋利確のみは利益が右に薄く損失が左に厚い形なので、平均やシャープを磨くより**左裾を測る道具**を先に作るのが筋。計算資源が潤沢という条件は D1（モンテカルロ）と A（purged CV 多数フォールド）に最も効くため、リソース配分とも整合する。

### 追加・格上げすべき論点

1. **「損切り禁止」はレバレッジ下で前提破綻 → 強制ロスカット（追証）の明示モデル化が最優先。**
   信用建ては委託保証金維持率（追証ライン）を割ると、本人の意思に関係なく強制決済される。含み損を無限に抱え続けられる作りは生存率の過大評価。**KPI は「何回・いつ強制決済されたか」を最重要に。** → 本件は **PR #4（Week 0.5）で着手済み**。本レビューはこれが入った前提で次段を組む。

2. **レバETFの逓減（ボラティリティ・ディケイ）:** 1570.T は2倍レバなので日次リバランスの経路依存により長期積立で逓減する。「長期保有の構造的減価」を独立シナリオとして1本持つべき（Codex も D1 の落とし穴で言及）。

3. **F の seed 保存は実は最優先級:** 再現性がないと以降の統計検証（A）が成立しない。Week 1 で確実に固定する（PR #4 で着手済み）。

### 順序の微修正案
着手初日に「強制ロスカット発火ロジック＋seed固定」を先に入れる（→ PR #4 で完了）。以降は上記ロードマップ通り。**派手な最適化（B）は最後**——土台が緩いまま最適化すると「精密に間違える」だけ。
