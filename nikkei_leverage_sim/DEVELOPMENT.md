## 1. 全スタディの到達点マップ

本プロジェクトは「日経2倍レバ ETF（1570.T）を**信用ロング・損切りなし・積立・利確**で運用したら？」という一つの問いを、
角度を変えた複数スタディで**自分の結論を疑いながら**検証してきた。各スタディは独立に再現でき、各 `REPORT_*.md`
冒頭の引用ブロックに**再現コマンド**がある。

| スタディ | 問い | レポート | 一行結論 |
|---|---|---|---|
| 本体3版比較 | 毎日最適化で安定して稼げるか | `REPORT_REAL.md` | 12.4年で税後+8.5〜10.7%。だが勝率100%は**損切りしないだけ**（76%の日が含み損・最長2.1年塩漬け） |
| 戦略バリアント | 一括売却で「気持ちよく利確」できるか | `REPORT_VARIANTS.md` | `bulk_pct 3〜5%` で含み損日 76%→43%・最長塩漬け 534→102日。体験は改善 |
| 積立×Exit比較 | ¥10Mをどう積立→いつ売る | `REPORT_ACCUMULATION.md` | 観測上は VA+hold 最良。だが**統計的有意でなく OOS で崩壊**（過剰最適化の実例） |
| ストレス | テール耐性（暴落生存） | `REPORT_STRESS.md` | 歴史的には全危機生存。だがブートストラップで ¥5M に**追証1.0%・破綻0.3%**の無視できないテール |

## 2. 横断的に確立した結論（個別スタディに依らず頑健）

1. **タイミングの α は無い。** 本戦略の小さな黒字は「押し目買いの妙」ではなく、薄く建てた口座が市場ドリフト（β）を
   拾っているだけ（`VALIDATION`）。**「有意なエッジの無い戦略のレバレッジ＝増幅されたβ」**。
2. **「綺麗な右肩上がり・勝率100%」は損切りしないことの裏返し。** 含み損が在庫として裏で滞留する（`REAL`）。
   評価は実現益でなく「含み損ピーク・最悪日資産・資金拘束日数・含み損継続日数」で行う。
3. **高リターンは構造的に深い DD を伴う。** 2倍レバで上位リターンを狙うと最大DD ~46〜55% は回避不能（`ACCUMULATION`）。
4. **単一の勝ちプラン選択は過剰最適化。** グリッド最良は統計的有意でなく OOS で順位崩壊。**勝つのはプランでなくレジーム**
   （`ACCUMULATION`/`REGIME`）。
5. **結論はレジーム依存。** 「hold 最良・exit 逆効果」は追い風相場の関数で、逆風では逆転（現金退避・トレンド+利確が勝つ）。
   buy&hold 2倍は失われた10年で逓減＋金利に食われ ≈−98%（`REGIME`）。
6. **生存閾値も追い風限定。** ¥3.3M(3倍)は逆風で債務超過、¥5M(2倍)も自己資金 −33〜−80%。真に安全なのは ≈無レバの ¥100M のみ（`REGIME`）。
7. **最大の執行リスクは「寄付を取れる前提」**（不利約定で−34%）。手数料・金利・スリッページ水準には頑健（`EXECUTION`）。

> 一言: **このプロジェクトの主要な成果は「儲かる戦略の発見」ではなく、「綺麗な右肩上がりが実は β＋含み損在庫であり、
> 追い風相場限定だった」ことを多角的・統計的・逆風実データで暴いたこと。** 新スタディもこの懐疑的スタンスを継ぐ。

## 3. 設計の不変条件・規約（変更時は厳守）

- **損切りなし / ルックアヘッド厳禁 / 制度イベントは記録のみ / 再現性（seed固定・外部通信なしテスト）** — 詳細と検証テストは [`../CLAUDE.md`](../CLAUDE.md)。
- **コア無改変・独立サブパッケージ。** 新しいスタディは `src/` に手を入れず独立フォルダに作る（`variants/`・`accumulation_study/`・`regime_study/` が前例）。
- **コスト前提の公平性（2系統）。** コアエンジン系（信用¥100M・実コスト）とグリッド系（現金¥10M・理想化＋感応度）は
  混ぜて数値比較しない。新スタディはどちらの系統かを明示し、その系統の前提に揃える（`REPORT_FAIRNESS.md`）。
- **レポートは GitHub/モバイルでそのまま読む前提。** Markdown＋相対パス画像を壊さない。各レポート冒頭に**再現コマンド**と
  **理想化の但し書き**を必ず置く。

## 4. 新しいスタディ/レジームを足すレシピ

`regime_study/` を雛形にすると速い。

1. **独立パッケージを作る**: `<study>/__init__.py`・モジュール群・`<study>/tests/conftest.py`
   （`src` と PKG を `sys.path` に追加。`accumulation_study/tests/conftest.py` をコピー）。
2. **エンジンを再利用**: 積立×Exit 系なら `from accumulation_study.engine/policies/run_study import ...`、
   追証/破綻なら `from nikkei_leverage_sim.backtest import run_backtest` ＋ `metrics.build_summary`（固定戦略 = `optimization.enabled=False`）。
3. **オーケストレータ**: `run_study.py`（→ `outputs/` に summary.json と per-plan rows.csv）。重い per-row は出さない/出すなら gitignore。
4. **統計検証**: `accumulation_study.validate.run_validation(prices_csv)` を再利用（ブートストラップ CI・置換 FDR・OOS・コスト感応度）。
5. **テスト**: 人工データのみ・外部通信なし。実データ依存の忠実度テストは**データ不在時に `pytest.skip`**（`regime_study/tests/test_build_target.py` 参照）。
6. **`.gitignore`**: per-row CSV（`<study>/outputs/*/daily.csv` 等）を除外。summary/rows/validation/PNG/report は追跡。
7. **Codex 静的レビュー**: `codex:codex-rescue` 経由（プロンプトに「pytest/-m pytest」を入れない・「静的レビューのみ、テストはローカル全件パス」と書く）。
8. **レポート生成 + 登録**: `make_report.py` で `REPORT_<NAME>.md`。`../CLAUDE.md`・`README.md`・本ファイル §1 に1行追記。重要な非自明知見はユーザーメモリにも残す。

## 5. 次の方向性（ロードマップ）

研究は「エッジ無し・β・追い風限定」へ強く収束済み。**同じ銘柄・期間でエッジを探し続けても同じ非有意が出るだけ**なので、
価値が高いのは以下。

- **B. β と認めた上で「最適な器」を設計**（実務着地・推奨）: 破綻確率 × 最大DD × 快適さ（利確頻度）のフロンティアを描き、
  **無レバ指数 DCA との公平比較**で「そもそも2倍レバを使う意味があるのか」に答える。`benchmark.py`（DCA 比較）と
  `accumulation_study`/`regime_study` の資本・破綻エンジンを束ねる新スタディ。
- **C. 全検証を1本の verdict に統合**（公開用・書き上げ）: 散在する 9 レポートを「確かに言える/言えない」の最終結論へ。
  新規知見は増えないが資産が完成する。GitHub/モバイル前提のランディング更新も。
- **D. 本物のエッジの厳密探索**（期待値低）: ボラターゲティング・OOSで実際に効くトレンドフィルタ・マクロレジーム等を
  **nested CV / 適切な OOS** で。同じ銘柄・期間では出ない可能性大。

### 精緻化（小粒・任意）
- regime のファイナンスを**日次金利**へ（現在は年平均近似）。スプレッド感応度の明示。
- レジーム窓を**ローリング/重複**で増やし、符号の一貫性をさらに堅く。
- グリッド系を**コスト統一版**でも併掲（現在は理想化＋20bps感応度のみ）。ただし系統間比較の罠に注意。
- 合成 bull ベースライン vs **実 1570.T** の差分を明示（現在は較正で一致を確認済み）。
