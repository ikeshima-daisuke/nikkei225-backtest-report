# シミュレーション条件の公平性監査

> **目的**: 既存レポート群の比較条件が、同一ファミリー内で公平か、ファミリー横断で混同されていないかを監査する。
> 🔴 **結論先出し**: 2ファミリーはそれぞれ内部整合; `regime_study`で1件の不整合を発見・修正済; ファミリー横断の直接比較は不可。

## §2 公平な比較とそうでない比較

公平に比較できるのは、同じ実験ファミリー内だけである。

coreファミリーは、口座自己資金¥100M、建玉上限¥10M、信用金利2.8%/年、税20.315%、slippage 2bps、評価価格closeという同一エンジン上で動く。`REPORT_REAL` の3版は `apply_days` 1/5/21 と `n_trials`、DDペナルティの違いを見ているだけなので、少なくともコスト・資本・データ条件は揃っている。`REPORT_VARIANTS`、`REPORT_STRESS`、`REPORT_MARGIN_CALL`、`REPORT_EXECUTION`、`REPORT_VALIDATION` も同じcore前提で、差分はストレス条件、執行条件、固定default戦略などの意図的な切り分けである。

gridファミリーは、使える資本¥10Mを分母にした現金onlyの積立・Exitグリッドである。口座信用取引は使わず、手数料・税・スリッページは0に置く。そのうえで、往復20bpsのコスト感応度を別枠で見る。これは「買い方・売り方の形」を見るための理想化された比較であり、grid内では公平である。

一方、coreとgridの直接比較は無効である。理由は2つある。第一に、coreは¥100M口座に対して建玉上限¥10Mを使う信用口座で、gridは最初から¥10Mを使える資本として扱う現金onlyである。第二に、coreはslippage 2bps、信用金利2.8%、税20.315%を入れるが、gridの主分析はcost_bps=0の理想値である。したがって「coreの総リターン」と「gridの総リターン」をそのまま横に並べると、分母とコストの両方が違う。

横断的に見るなら、`REPORT_REAL` §10 と同じく¥10M分母へ取り直すか、grid側にコスト感応度帯を添えて読む必要がある。実務的には、coreの遊休担保¥90Mを除外した¥10M資本ベースの再表示と、gridの0bps理想値〜往復20bps感応度の幅を並べるのが最低条件である。

## §3 発見した不整合と修正

発見した唯一の実質的不整合は、`regime_study` の生存検証における口座信用金利である。

合成2倍ETFの内部ファイナンスは、すでに `financing.py` でレジームawareだった。具体的には、JPY無担保コール翌日物の年平均を使い、1990-1992年の4.58〜7.38%の高金利を `(leverage - 1) * call_rate` として合成ETFのドラッグに入れていた。ところが、生存検証の投資家口座側の信用金利だけは、追い風eraの2.8%を全レジームに固定していた。これは、1990年代の高金利レジームを楽観的に扱う不整合だった。

修正後は、口座信用金利も次の式でレジームawareにした。

```text
account_margin_rate(regime) = mean(call_rate) + spread
spread = 2.8% - mean(call_rate over 2014-2026 bull window)
```

`financing.py` 上の較正値は、`CORE_DEFAULT_MARGIN_RATE=0.028`、2014-2026 bull窓の平均call rateが0.000476923076923077、したがってspreadは0.027523076923076922である。これにより、bull窓は2.8%を再現し、逆風レジームだけが史実の高金利に応じて重くなる。

| レジーム | 期間 | `account_margin_rate` | 表示 | 根拠 |
|---|---|---:|---:|---|
| `bubble_burst` | 1990-01-04〜1995-12-29 | 0.0703 | 7.03% | `survival.json` |
| `lost_decade_1` | 1990-01-04〜2003-04-30 | 0.0470 | 4.70% | `survival.json` |
| `deflation_grind` | 2000-01-04〜2012-12-28 | 0.0289 | 2.89% | `survival.json` |
| `gfc` | 2007-06-01〜2009-03-31 | 0.0310 | 3.10% | `survival.json` |
| `two_lost_decades` | 1990-01-04〜2013-12-30 | 0.0396 | 3.96% | `survival.json` |
| `bull_real` | 2014-01-06〜2026-06-05 | 0.0280 | 2.80% | `survival.json` |

この修正は、bull baselineを動かさない。`bull_real` の¥5Mは +70.27%、¥3.3Mは +106.47%で、既存の丸め表示（+70.3% / +106.5%）と一致する。

## §5 残る既知の前提差（意図的）

**cost_bps=0理想化 + 20bps感応度（gridファミリー）**

`accumulation_study` と `regime_study` の積立gridは、買い方・売り方そのものの形を見るために、手数料・スリッページ・税を0に置く。これは回転の多いExit系を有利にするので、現実の絶対収益として読むには楽観的である。ただし同じgrid内の全プランに同じ理想化を適用しているため、grid内順位の記述としては整合している。さらに `REPORT_ACCUMULATION.md` では往復20bps感応度を別に出しており、理想値だけで結論を固定しない設計になっている。

**synthetic-vs-real in regime bull baseline**

`regime_study` の逆風期は、1570.Tが未上場だった1989-2013をN225から合成する。これは実ETFではないため、実在価格のバックテストとは性質が違う。一方、2014-2026の実1570.Tで較正され、betaは1.9561、日次相関は0.99275、累積は実1570.Tと合成が12.9191で一致している。bull baselineの口座信用金利も2.8%に戻るよう較正したため、逆風期だけを史実金利へ拡張するという意図は明確である。

**fixed-vs-optimized strategy**

coreの `REPORT_REAL` はウォークフォワード最適化のapply_days差を比較する。一方、生存検証やvalidation系は固定default戦略を使う。これは同じ問いではない。最適化器の優劣を見る分析と、固定戦略が資本薄化・逆風で破綻するかを見る分析を分けるための設計であり、混ぜて直接順位づけしない限り許容できる。

## §6 但し書き / 再現コマンド

この監査は、設定ファイル（`examples/*.yaml`）、`financing.py`、`summary.json`、`survival.json`、および各 `REPORT_*.md` の前提記述に基づく。§1の個別割当（各 core スタディの最適化/資本スコープ）は各レポート冒頭の前提と CLAUDE.md の記述から補完した。

`regime_study` の期間カウントには、ファイル内で表記差がある。較正部と `REPORT_REAL` は2014-01-06〜2026-06-05を3,032営業日としている一方、`summary.json` の `bull_real` レジームは同期間を3,034日としている。本監査では、core実データ比較は3,032営業日、`summary.json` のレジーム内値はJSONの値を優先して読む。

再現コマンドは以下。いずれも `nikkei_leverage_sim` ディレクトリを基準に実行する。

```powershell
python -m regime_study.run_study
python -m regime_study.survival
python -m regime_study.validate
python -m regime_study.make_report
```

本監査上の最終判断は次の通り。core内比較は公平。grid内比較も公平。coreとgridの直接比較は、¥100M信用口座と¥10M現金only、かつcore-costとidealized-tradeという前提差があるため不可。`regime_study` の唯一の実質的不整合だった口座信用金利固定は、レジームaware化により修正済みである。
